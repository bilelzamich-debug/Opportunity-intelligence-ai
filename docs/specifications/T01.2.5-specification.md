## 5. Architectural constraints

1. **C1 — Reachability from ACTIVE forbids archiving.** The single hard rule (AC1).
2. **C2 — Reachability is by lineage traversal**, upstream from ACTIVE objects: an object supporting an ACTIVE object is its *ancestor*. `ancestors()` is the ratified primitive.
3. **C3 — Only `ACTIVE → ARCHIVED`.** No terminal state may transition.
4. **C4 — Skeleton permanent**: identity, type, version, `lineage_id`, lineage refs, fingerprint, provenance, status, `status_reason`, attribution.
5. **C5 — Traversal never breaks** after archival (AC2).
6. **C6 — Nothing hard-deleted** (I4).
7. **C7 — No cascade from ARCHIVED** (M-65).
8. **C8 — Maintenance operation**: explicitly invoked, never automatic. No scheduler, no GC, no heuristics.
9. **C9 — Objects authoritative, graph derived** (N-6).
10. **C10 — Backward compatible**; `transition()` keeps working for every other status.
11. **C11 — Fail closed** where unspecified.

## 7. Document conflicts

**One apparent conflict, resolved by the crosswalk.** IOM §2.1 says the ARCHIVED authority is *"Undefined (MISSING-31)"*, which would make the task unimplementable. But IOM MISSING-31 = canonical **M-38**, closed by N-12, which supplies exactly the trigger (unreachability) and owner (maintenance operation). Under Article XI, decision records outrank the IOM. **No unresolved conflict.**

A second, resolved: N-12's Known Tension says REJECTED objects are *"subject to tiering like any other unreachable object"*, while R-2/IOM forbid transitioning a terminal state. These are compatible once tiering (content) is distinguished from the `ARCHIVED` status transition — see A4. Only the ratified transition is implemented.

## 8. Implementation plan

Smallest architecture-compliant change; all additive.

**Step 1 — `oip/retention.py` (new module).** `ReachabilityIndex` computing the protected set = every ACTIVE object plus all their `ancestors()`. `ArchivalCandidate` / `ArchivalAssessment` (frozen, itemised reasons). `RetentionPolicy` — a maintenance operation exposing `is_archivable()`, `assess()`, `candidates()`, `archive()`, `archive_all()`. It owns no storage; store and graph are supplied.

**Step 2 — Guard `store.transition()`.** Refuse `→ ARCHIVED` when the object is reachable from an ACTIVE object. This closes the documented hole at the single mutation point, so no path can bypass it. A new `ReachabilityError`. The guard is inert unless a graph is available.

**Step 3 — Skeleton preservation assertions.** `RetentionPolicy.verify_skeleton_intact()` proving, after archival, that identity/type/version/lineage_id/lineage refs/fingerprint/provenance/status/attribution all still resolve and traversal still works.

**Explicitly NOT built:** content eviction or any storage tier (A1, unspecified); scheduling or GC (A5); age heuristics (N-12 Option B rejected); hard deletion (I4); cascade from ARCHIVED (M-65); archival of failure records or configuration (N-12 excludes them); any change to `CASCADE_TRIGGERS`, acceptance, confidence or ownership.
