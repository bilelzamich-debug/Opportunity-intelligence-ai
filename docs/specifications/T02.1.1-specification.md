### 4.2 What the task therefore asks

The task asks me to *implement* the resolution of an **open** marker:

- **AC1 — "closed taxonomy".** No ratified source enumerates a single source
  type. The IOM's only example value is `customer_review_corpus` (§3.1 worked
  example). Producing a closed enumeration means **inventing the vocabulary**
  that M-16 exists to define.
- **AC2 — "per-source trust rating".** The IOM marks `source_reliability`
  optional and annotates it "(OPEN QUESTION-28)", which the crosswalk subsumes
  into M-16. Its scale, range, semantics and default are undefined. Choosing
  them invents the trust model.
- **AC3 — "learnable target for P8".** The set of learning targets is **M-02**
  ("What the platform learns — the target of change"), which is **also open**
  and on the standing forbidden-closure list. Declaring source trust a learning
  target adds a member to an undefined set.

Each of the three acceptance criteria requires closing an open marker by
implementation choice.

### 4.3 Why this cannot be failed closed in code

For prior gaps (M-36 policy, C-02, M-65) the fail-closed move was available:
*refuse the operation and surface the marker*. That works when the gap concerns
an **action** the platform may take.

Here the gap **is the deliverable**. A "source taxonomy" that enumerates
nothing is not a fail-closed implementation of T02.1.1 — it is an empty module
that satisfies no acceptance criterion. There is no partial, honest
implementation: any `SourceType` enum I write is invented vocabulary, and
`AGENT-PLAYBOOK` §2 **F3** states markers "close only by recorded decision.
Implementing around a gap does not close it."

### 4.4 Forbidden actions this would require

| # | Forbidden action | How T02.1.1 would require it |
|---|---|---|
| **F2** | Making an architectural decision yourself | The taxonomy, trust scale and learning-target membership are architectural |
| **F3** | Closing a marker by implementation choice | M-16 (and a slice of M-02) would be closed in code |
| **F12** | Silently proceeding past a contradiction | The backlog says implement; v2 §13 says unresolved |

`AGENT-PLAYBOOK` §1: *"when a task appears to require an architectural
decision, **stop and escalate** … deciding it yourself is the one thing that
breaks this project."*

The task carries the **⚠** escalation flag, and **F6** forbids self-approving
an escalation.

## 6. What is required to unblock

A ratified decision record closing **M-16**, specifying at minimum:

1. **The closed source-type taxonomy** — the exhaustive member list.
2. **Per-type eligibility** — which types may be acquired, and under what
   conditions (distinct from M-18 licensing, which is `T02.1.2`).
3. **The trust model** — scale, range, semantics, default for an unrated
   source, and its relationship to `evidential_support` (IOM §3.1 notes that
   absent this, "all sources weigh equally").
4. **Learning-target status** — whether source trust is a legitimate P8
   learning target, which touches **M-02**; and if so, who may write it and
   under what authority (cf. M-43, Feedback Engine write target).

Items 3 and 4 also determine whether `source_reliability` remains optional
(IOM §3.1) or becomes required — a change to the **frozen** Evidence contract,
which under **F5** may only be made through the annotation layer by decision.
