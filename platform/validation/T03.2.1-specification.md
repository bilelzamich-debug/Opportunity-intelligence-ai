## 3. The design: wiring, assembled — nothing rebuilt

### 3.1 What already exists (untouched)

- `oip/semantic.py` — `AnchorVerifier` (frozen P1): checks every presented
  `AnchorClaim`; None from the provider → FAIL "fabricated location";
  missing components → FAIL; counts `checked`/`failed`; `covers_paraphrase_drift=False`.
- `oip/fact.py` — `fv6_anchor_verification`: SKIP when not a Fact, when no
  payload, or when no verifier is installed (with the M-67 text); otherwise
  delegates wholly to the verifier.
- `oip/store.py` — `anchor_verifier` slot on the store; `_evaluate` reads it
  live at every write; `write_fact` passes the Fact payload into the context.
- `oip/anchoring.py` — `evidence_span_provider(content)` (resolves BOTH the
  positional `chars a-b` locator by direct slice and the T03.1.1 verbatim-span
  convention by unique occurrence) and `fact_anchor_claims(fact)`.

### 3.2 What this task adds (the whole of it, in the P3 bridge module)

```
store_span_provider(store) -> SpanProvider
    resolve anchor.evidence_id -> store.get_evidence(ref)
    no payload (dangling ref)                 -> None  (fails closed)
    not EvidenceContent.is_verifiable_in_place -> None  (N-15 predicate is
        the single authority; REFERENCE mode never resolves)
    FULL payload                              -> evidence_span_provider(
        content.content)(anchor)   # non-None by the E-V3 constructor

install_anchor_verification(store, *, span_provider=None, claims_of=None,
                            replace=False) -> AnchorVerifier
    builds the ratified AnchorVerifier with store-wide defaults
    (claims_of = fact_anchor_claims over ctx.fact);
    refuses to clobber an existing installation unless replace=True
    (register-conflict precedent: loud refusal, never silent overwrite);
    binds it to store.anchor_verifier and RETURNS it (T03.2.3 reads its
    counters from the return value or the slot).
```

`fact.py`, `store.py`, `acceptance.py`, `semantic.py`, `extraction.py`:
**zero edits.** The change is two functions and an error path in the one
module this phase owns (`oip/anchoring.py`), plus tests and verification.

### 3.3 AC satisfaction

- **AC1** — every Fact accepted through `store.write_fact` with a verifier
  installed has every attachment's claim components located at the stated
  anchor by the ratified Layer-1 machinery. The engine path (extract) already
  anchors via the verbatim span + positional locator; the acceptance check
  re-derives both from live store state, so a Fact whose anchor would not
  resolve could not be written at all.
- **AC2** — a fabricated anchor (out-of-bounds locator, absent span,
  ambiguous verbatim, dangling evidence_ref, REFERENCE-mode content) yields
  a FAIL from `AnchorVerifier`, the store's acceptance refuses the write,
  the failure is recorded on the store's failure log (N-10), and no Fact is
  persisted. The message is the verifier's own ratified text.
- **AC3** — `fv6_anchor_verification` is unconditional in `FACT_RULES`:
  with the verifier installed it runs on EVERY `write_fact`, including every
  T03.1.4 merge re-version (all accumulated attachments re-checked against
  live content — immutability makes this deterministic). "100 percent of
  Facts" means every Fact persisted through the Fact write path. Mechanically
  demonstrated: `verifier.checked` equals the total attachment count of
  accepted Facts across the corpus; the verification count per write equals
  the attachment count of that write.

### 3.4 Boundaries stated, not hidden

- **Default OFF.** An unconfigured store keeps the P1-pinned behavior (F-V6
  SKIP with the M-67 text). T03.2.1 delivers the install path; platform
  assembly (or the next phase's orchestration wiring) decides to install.
  Flipping the default would change frozen-module behavior and silently alter
  3,610 tests' baseline — a bigger decision than this task.
- **Payload-free FACT shells.** A FACT persisted through the generic
  `store.write()` path carries no payload and is verified by no F-V rule —
  discovered by live probing during this task's analysis and recorded as
  FINDING T03.2.1-F1 for the Project Owner (pre-existing P1 attribute/payload
  split; not introduced here; not fixed here). It does not weaken AC3 as
  scoped: a shell has no anchors to verify — but it is a graph-surface
  observation the Owner should decide about.
- **REFERENCE-mode facts.** Hand-built Facts attaching REFERENCE-mode
  Evidence fail closed ("does not resolve") — conservative and correct
  under F-V6's wording (the claim's presence at the anchor must be
  demonstrated, not assumed). The engine never produces such Facts:
  extraction already refuses REFERENCE input (T03.1.1).
- **Paraphrase drift is NOT detected.** Layer 1 catches fabricated location;
  the PASS text says so; `covers_paraphrase_drift=False`; M-67 stays open
  until Layer 2 sampling (T03.2.2) and the published rate (T03.2.3) run.
- **`anchor_failure_rate` is not the hallucination rate** — the property is
  named and documented as such in the frozen verifier; T03.2.3 consumes it.

### 3.5 Failure and refusal semantics

Every refusal is an ordinary acceptance failure: `WriteRejectedError` with a
failure record in the store (N-10), no Fact persisted, no partial graph
mutation (the write is atomic under N-6). The verifier never mutates the
Fact or Evidence; it only reads. Install conflicts raise `AnchoringError`
(reused from `oip.extraction`, this module's established error vocabulary)
with `replace=True` as the only override.

## 4. Test plan (written after adversarial probes)

- Probes first (mutation-of-attack, `probe_t03_2_1.py`): fabricated locator
  through the real engine's store; shifted locator; verbatim-span forgery;
  dangling ref; REFERENCE payload; double-install; replace=True; uninstalled
  store behavior unchanged; merge re-version re-verifies the OLD attachment;
  checked-count arithmetic; provider purity (slice only); concurrency:
  install during a write cannot tear a verdict (single read under lock).
- Contract tests (`tests/test_anchor_wiring.py`): AC1/AC2/AC3 as properties
  over the live corpus; N-4 determinism (same store state → same verdicts,
  across replays); regression guard: default store still None.
- Mutation harness (`mutate_t03_2_1.py`): each mutant must die — the
  most important admit-what-must-be-refused mutants: clobbering install,
  None payload passed through as PASS, REFERENCE content treated as
  resolvable, skip-instead-of-fail on a configured verifier's empty claims.
