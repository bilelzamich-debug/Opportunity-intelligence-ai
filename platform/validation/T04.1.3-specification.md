Acceptance criteria (verbatim):

2. **Population never widened without supporting Facts (P-I3)**

Status at checkpoint:

- AC1 is **already enforced end to end** by the authoritative P-V3
  (`pv3_population_specific`): non-empty and not a generic descriptor
  (`GENERIC_POPULATIONS`), at store acceptance on the standalone path and in

  T04.1.3 adds no second P-V3 and changes none of this.

  enforce P-I3 at write time**. A versioned inference can widen the affected
  population (or raise `population_size_estimate`) without additional
  supporting Facts; only the detective `ProblemIntegrity._check_pi3()`
  discovers the violation afterwards. T04.1.3 closes exactly this gap.

## 5. Versioned P-I3 gate (the flow, ordered)

Runs only in versioned mode (`predecessor_id is not None`); the standalone
path is untouched. No state changes precede the gate; the gate runs
entirely BEFORE the predecessor transition, so a refusal leaves the
predecessor ACTIVE and no successor stored.

1. **Existing pairs** (after predecessor resolution and the P-I1 chain
   check, in the versioned preamble): enumerate the predecessor's lineage
   via `store.versions_of(store.resolve_lineage(predecessor_id))`; for each
   CONSECUTIVE pair (earlier, later) of registered payloads, evaluate the
   authoritative `later.widens_population_of(earlier)` and
   `later.adds_support_over(earlier)`. Any pair that widens without added
   support → refuse with `POPULATION_WIDENED_WITHOUT_SUPPORT` naming the
   violating pair. A clean latest version never bypasses an earlier
   violation (the T04.1.2 chain principle).
2. **New pair** (after composition, before the authoritative dry-run and
   the transition): evaluate the authoritative
   `successor.widens_population_of(predecessor_payload)` and
   `successor.adds_support_over(predecessor_payload)`.
   - widens AND no additional supporting Facts → refuse with
     `POPULATION_WIDENED_WITHOUT_SUPPORT`, naming both populations (and the
     raised estimate where that is the widening form);
   - widens WITH additional supporting Facts → allow (P-I3 satisfied);
   - equal, narrowing, or undecidable (merely different wording) → allow
     (S-3 conservative semantics preserved; the engine never guesses).
3. On success the flow continues exactly as T04.1.2 defined it:
   dry-run → transition → write.

Both steps use ONLY the public authoritative methods; no second definition
of widening exists in the engine.

## 6. Population semantics

- `affected_population` and `population_size_estimate` are carried exactly
  from the request (N-4). The engine never derives, infers, normalizes, or
  widens a population.
- Widening is exactly what `Problem.widens_population_of` recognizes:
  a strict term-subset (qualifying terms dropped) or a raised
  `population_size_estimate` over a present earlier estimate. Anything else
  — including differently worded descriptors — is undecidable and allowed.
- `population_size_estimate` request semantics unchanged (optional,
  non-negative). No traceability mechanism is added; an unauthorized raised
  estimate that the authoritative semantics classify as widening is refused
  without supporting Facts, exactly like a textual widening. No M-12
  (scales/bands) work.
- No lexical population rules, no semantic similarity, no LLM
  classification, no inferred terms, no thresholds, no severity/frequency
  logic, no taxonomy logic. M-12, M-21, M-22 remain OPEN.

## 7. Failure semantics and atomicity

- The gate precedes every irreversible step: on refusal the predecessor is
  still ACTIVE, no successor exists, no registry/graph/lineage mutation
  occurred, and the refusal is recorded in the `InferenceLog` (N-10) before
  the exception is raised.
- No SUPERSEDED → ACTIVE restoration exists or is attempted (R-2 terminal;
  T04.1.2 established the surviving-state behavior for post-transition
  failures, which this task does not touch).
- The stage is distinguishable from every other stage and reason token;
   `attempted` is True (the judgement ran over evidence in hand).

## 8. Refusal stage (N-10, closed-set extension)

| Stage | Meaning | `attempted` |
|---|---|---|
| `POPULATION_WIDENED_WITHOUT_SUPPORT` | the authoritative P-I3 semantics classify the (existing pair, or predecessor → proposed successor) as population widening without additional supporting Facts | **Yes** |

Reason tokens: `PAIR_WIDENED_WITHOUT_SUPPORT` (an existing lineage pair) and
`SUCCESSOR_WIDENS_WITHOUT_SUPPORT` (the proposed successor), both carrying
the two populations in the detail.

## 9. What is deliberately NOT implemented

- No second P-V3 (acceptance/request paths remain the only P-V3 enforcers).
- No semantic/LLM specificity judgement — P-V3's structural check is all
  that is ratified; the specificity residual stays reported-open [M-21].
- No population derivation from Facts (N-4).
- No severity/frequency/population scales or bands (M-12, T04.1.4); no
  estimate-traceability mechanism.
- No taxonomy constraints (M-21, T04.1.6); no deduplication or DUPLICATES
  links (M-22, T04.1.5).
- No changes to the detective `ProblemIntegrity` P-I3 (it remains
  authoritative for paths no single write controls).
- No T04.2.1/P4 exit work; no LLM/network/external APIs/UI/observability;
  no new modules; module count stays 39; no pin changes.
