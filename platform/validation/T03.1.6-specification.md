## 7. The detection primitive (exact specification)

```python
def established_contradiction(left: Claim, right: Claim) -> bool:
    """F-C1 R1 (RATIFIED 2026-09-09): an established contradiction
    exists iff ALL six conditions hold. Fail-closed: "cannot establish
    contradiction" never links. Pure function of the two claims;
    symmetric; never inspects claim_type/attributed_to (F-C1 R3)."""
    if not left.same_subject(right):                 # C1
        return False
    if not left.same_predicate(right):               # C2
        return False
    if not left.same_qualifier(right):               # C3  (Q2)
        return False
    if left.value is None or right.value is None:    # C4  (incomparable)
        return False
    if left.value.unit != right.value.unit:          # C5  (incomparable)
        return False
    return not left.value.agrees_with(right.value)   # C6  (disagreement)
```

- **Inputs:** two frozen `Claim` instances (any provenance).
- **Output:** `bool` — `True` iff C1∧C2∧C3∧C4∧C5∧C6.
- **Deterministic:** yes — boolean composition of `_normalise` string
  equality and one IEEE-754 float comparison (`|a−b| > max(p_a, p_b)`),
  no state, no I/O, no clock (N-4 structural posture).
- **Failure behavior:** never raises (Claim/Quantity invariants are
  enforced at construction; every undecidable case returns `False` —
  fail-closed by construction, INV-C5).
- **Symmetric** in its arguments (all six conditions are symmetric).
- **Allowed location:** `platform/oip/extraction.py`, module level,
  public (it *is* the F-C1 R1 rule; direct unit-testability; precedent:
  tests already import module-level names from `extraction`).
  NOT in `claim.py` (byte-pinned, would extend S-3's module), NOT a
  `Verdict` member, NOT a new module (module-count pin).
- **Not** `not values_agree(...)`: `values_agree` conflates one-sided
  quantification and unit mismatch with disagreement (F-C1 R1/R9) —
  the decomposition above is the ratified correction of exactly that.

## 9. Lifecycle invariants (verified against R-2, F-C1 INV-C1..C4)

- New Fact: `status=ObjectStatus.ACTIVE` at construction (existing
  separate path) — unchanged; CONTRADICTS adds no transition.

  refusal stages/reasons are introduced.
- Detection is a **report, not a gate**: no extraction is refused
  because of contradiction (N-10 untouched; the closed reason set is
  not extended).

Historical pairs (both Facts created before implementation) are never
linked: no retroactive scan exists; every pair is assessed exactly once
at the **later** member's creation.

## 11. F-V4 interaction (Q3 — type-blindness, verified)

The detector operates on `Claim` objects only; `claim_type` and
`attributed_to` are `Fact`-payload fields — the predicate cannot see
them even by accident. Required identical behavior for identical
content: ASSERTION×ASSERTION, ASSERTION×ATTRIBUTED_OPINION,
ATTRIBUTED_OPINION×ASSERTION, ATTRIBUTED_OPINION×ATTRIBUTED_OPINION
(any speakers). The detector also never *writes* those fields — the
separate path's F-V4 population logic (`claim_type=request.claim_type`,
`attributed_to=… if ATTRIBUTED_OPINION else None`) is untouched.
F-V4 INV-1..INV-4 and the `CLAIM_TYPE_CONFLICT` gate are unaffected.
