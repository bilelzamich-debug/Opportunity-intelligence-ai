## 7. The selection primitive (exact specification)

```
selection(fact_object_id, stratum_key, policy) -> bool
  canonical := f"{policy.version}:{policy.salt}:{fact_object_id}:{stratum_key}"
  digest    := sha256(canonical.encode("utf-8")).digest()[:8]
  return    int.from_bytes(digest, "big") / 2**64 < policy.rate
```

- `stratum_key := f"{source_type}:{confidence_band}"` — values from the
  ratified closed vocabularies (R4), so the canonical string is stable.
- **Pure**: no clock, no RNG, no store reads, no enumeration state
  inside the function (R2). All inputs are frozen data.
- **Properties to test** (N-4; never equality with a pinned list):
  same inputs → same decision (also across processes: sha256 only);
  `rate=0.0` → never; `rate=1.0` → always; monotone in rate (selected
  at r ⇒ selected at any r′ > r); a new policy version/salt re-derives
  eligibility independently of prior selections.

## 8. Stratification, eligibility and dedup (exact)

1. For each `EvidenceAttachment` of the accepted Fact: resolve its
   Evidence (installer-closure store lookup), `st := classify(
   evidence.provenance.source_type )`, `b :=
   ConfidenceBand.for_value(attachment.extraction_confidence)`;
   stratum `(st, b)`.
2. The Fact's **eligible strata** = the distinct strata of its
   attachments (F-V1 guarantees ≥ 1). Never only the first attachment
   (R5).
3. For each eligible stratum, evaluate §7. A stratum whose hash is
   under threshold **selects** via its contributing attachment.
4. If ≥ 1 stratum selects: **one audit unit** is created. Tie-break
   among selecting strata: the lexicographically smallest
   `(source_type, confidence_band)` — deterministic and defined, not
   list order (R5).
5. **Dedup**: the audit-unit key is `(fact_object_id, policy_version)`.
   If the register already holds a selection for that key, no new
   selection is created (single audit per audit configuration/version,
   R5). A merged Fact is a **new version = new `object_id`** (R-1) and
   therefore a new identity for selection purposes.
6. The audit unit **retains**: the Fact identity, the selecting
   attachment's `evidence_ref` and `positional_anchor`, the
   `source_type`, the `confidence_band`, the `policy_version`, and
   `selected_at` (R5).

## 9. Recording semantics (exact)

- **`Judgement`** (closed, enumerated by S-5; R7):
  `FAITHFUL | DRIFTED | UNSUPPORTED`. No other value can be recorded.
- **`AuditRecord`** (frozen dataclass, operational — N-10 outside the
  object model; R6): `fact_object_id`, `evidence_ref`,
  `positional_anchor`, `source_type`, `confidence_band`,
  `policy_version`, `selected_at`, and the judgement fields
  (`judgement: Judgement | None = None`, `judged_at`, `auditor` —
  absent until supplied).
- **`AuditRegister`** (append-only, `RLock`-guarded, process-local —
  the `FailureStore`/`DriftRegister` pattern; R6):
  - `select(record)` appends a **pending** record (judgement absent).
  - `record_judgement(fact_object_id, policy_version, judgement, …)`
    completes the pending record **exactly once** — rejected if no
    pending selection exists, or if it is already judged. The
    completed judgement is immutable; no double judgement, no
    judgement on unaudited Facts, no deletion, no FAITHFUL default
    (R7).
  - Read surface (minimal; **no rate computation — that is T03.2.3**):
    `__iter__`, `__len__`, `for_fact(...)`, `pending()`.
- The register shares no type with the object model, returns no
  Intelligence Object, and never enters lineage (CI-1 discipline, R6).

## 10. The judgement-provider interface and AC2 (exact)

- **`AuditContext`** (frozen; what the platform owes the auditor, R11):
  the Fact's claim and `qualifying_context`, the selecting attachment's
  Evidence identity and `positional_anchor`, the **resolved anchored
  span text** (via the injected span-resolver callable — composition,
  no new import), `source_type`, `confidence_band`, `policy_version`.
- **`JudgementProvider`** (Protocol/ABC): `judge(context: AuditContext)
  -> Judgement`. The platform calls it **only** in the audit flow —
  never at acceptance (R1/R8). Human auditors implement it
  out-of-platform; fixture tests implement it in-platform.
- The platform performs **structural validation only** (closed
  vocabulary member, pending selection exists) and records exactly what
  the provider returns. **No semantic interpretation, NLP, LLM, or
  network** anywhere in the module (R8).
- **AC2 demonstration (mandatory tests, R11)**: a Fact whose anchor
  resolves and whose subject/predicate/value appear in the span —
  Layer 1 **PASSES** — but whose span text carries a meaning the claim
  subtly misrepresents (e.g. a dropped qualifier/hedge); the fixture
  provider returns `DRIFTED` (and, second fixture, `UNSUPPORTED`); the
  register records it. This demonstrates that Layer-2 outcomes are
  reachable for exactly the Facts Layer 1 cannot catch — the
  architectural satisfaction of AC2.

## 11. Non-gating wiring and lifecycle invariants

- `install_sampled_audit(store, policy, span_resolver=None, …)` —
  composition installer (the `install_anchor_verification` precedent):
  builds the closure (store + policy + span resolver), performs §8 for
  each accepted Fact, appends selections to its `AuditRegister`, and
  assigns `store.audit_sampler`. Returns the register (and/or sampler)
  for test/operational access.
- `store.py` additive change: `audit_sampler: object | None = None` +
  post-commit invocation after a successful Fact acceptance. Wrapped so
  that **any sampler exception leaves the acceptance standing** and is
  recorded as an N-10 operational failure through the failure surface
  available at the installation site. The store never evaluates
  anything (N-8 preserved).
- Default: `audit_sampler is None` → unwired, zero behaviour change
  (the "unwired by default" convention).
- **No lifecycle effect, ever** (R9): no status transition, no
  relationship, no Fact mutation follows from any judgement. An
  `UNSUPPORTED` Fact remains ACTIVE.

## 12. Sampling policy records (rate configuration — AC1)

- **`SamplingPolicy`** (frozen, immutable, versioned — N-7 discipline
  as infrastructure state under CI-1; R10): `version: int`, `rate:
  float ∈ [0.0, 1.0]`, `salt: str`, `recorded_at`. Policy **v1**:
  `version=1`, `rate=0.05`, fixed salt (*proposed*: `"f-a1-v1"`).
- Adjustment = a **new policy version recorded manually by the
  owner/operator** — never an in-place mutation, never automatic (R10).
  Policies are held with the audit surface (they are not engine
  `ConfigurationRecord`s — those are per-`Engine`; recorded in F-A1 so
  the placement is not silently re-derived).
- Every `AuditRecord` carries the `policy_version` that selected it
  (R10). **AC1 satisfaction**: "sample rate configurable" = the rate
  lives in a versioned policy record consumed by the installer and the
  selection function.
