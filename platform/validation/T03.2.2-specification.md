**Explicit non-conflict with S-5's "human audit" wording.** S-5 adopted
sampled audit as Layer 2 because semantic judgement does not scale to
100%. The *protocol* (sample, compare against source, record a closed
judgement, preserve provenance) is what this task implements. The
comparison itself is mechanical over S-3 components and a closed
conflict lexicon so tests can *demonstrate* detection rather than mock
it. Residual synonymy the lexicon cannot decide is UNAUDITABLE, never
FAITHFUL.

## 3. The design: protocol, assembled — nothing rebuilt

### 3.1 What already exists (untouched)

- `oip/semantic.py` — `AnchorVerifier._missing_components` (Layer 1).
- `oip/claim.py` — `Claim`, `Quantity`, `UNQUALIFIED`, `assess_equivalence`.
- `oip/fact.py` — Fact, attachments, `ClaimType`, qualifier, `attributed_to`.
- `oip/anchoring.py` — `evidence_span_provider` / `fact_anchor_claims`
  (injected at the call site; `audit.py` does not import anchoring, so
  the DAG and the ≤6-import budget hold).
- `covers_paraphrase_drift` on `AnchorVerifier` remains `False`.

### 3.2 What this task adds (`oip/audit.py`)

```
AuditConfig(sample_rate, seed)
    rate in [0.0, 1.0], finite, not bool; default 0.05 [S-5]
    0.0 disables sampling (empty sample, no silent verification)

AuditCandidate(fact, source_type, extraction_confidence)
    stratification key = (source_type, ConfidenceBand of extraction_confidence)

select_sample(candidates, config) -> unique Facts
    dedupe by object_id (first wins)
    per-stratum k = min(n, floor(rate * n))
    k never exceeds unique candidates
    rank = sha256(seed || object_id)  — no PRNG

audit_fact(fact, span_of, config) -> tuple[AuditRecord, ...]
    one record per attachment
    span_of(fact, attachment) -> str | None   (None = unverifiable)

run_sampled_audit(candidates, span_of, config, register)
    sample then audit; append-only AuditRegister [N-10]
```

### 3.3 Judgement procedure (stronger than Layer 1)

For each attachment of a sampled Fact, against the **resolved span**:

| Step | Outcome |
|---|---|
| Span is `None` (dangling, REFERENCE-mode, provider refused) | `UNAUDITABLE` — not a S-5 judgement; **not verified** |
| Span empty / whitespace | `UNAUDITABLE` — insufficient content; **not verified** |
| Layer 1 subject/predicate absent from the span | `UNSUPPORTED` (hallucinated location / fabricated components) |
| Material conflict detected (closed lexicon): negation polarity, antonym pair, quantity mismatch, year mismatch, attribution mismatch, dropped restrictor, qualifier tokens not supported by the span | `DRIFTED` |
| Layer 1 locatable **and** qualifier/value/polarity/attribution consistent with the span (substring/number/year support — acceptable paraphrase) | `FAITHFUL` |
| Remaining undecidable synonymy (no conflict, no support) | `UNAUDITABLE` — S-3 "do not guess"; **not verified** |

`UNAUDITABLE` is **not** a fourth S-5 judgement. S-5's three judgements
apply only to completed audits. Incomplete audits follow N-15/N-10:
recorded, not verified, never fabricated as FAITHFUL.

Fact-level roll-up over attachments (fail-closed):

`UNAUDITABLE` > `UNSUPPORTED` > `DRIFTED` > `FAITHFUL`

A Fact is `verified` only when every attachment is `FAITHFUL`.

### 3.4 Why this detects what Layer 1 misses

Layer 1 asks: *are the subject and predicate substrings of the span?*
The canonical counter-example already in `test_fact.py`:

> span: "some sellers occasionally report issues"
> claim subject/predicate: "sellers" / "report"
> Layer 1: **PASS** (`covers_paraphrase_drift is False`)

Layer 2 additionally inspects qualifier, quantity, polarity, certainty,
attribution, temporal markers and a closed conflict lexicon (`all`/`some`,
`consistently`/`occasionally`, `issues`/`failures`, `will`/`may`,
`increased`/`decreased`, …). The same case is `DRIFTED`.

Value is included here: `fact_anchor_claims` emits `value=""` so
acceptance-path Layer 1 does not check quantities. Layer 2 does.

### 3.5 Provenance on every record

Each `AuditRecord` answers:

| Question | Field |
|---|---|
| What Fact? | `fact_id`, `lineage_id`, `fact_version` |
| What evidence/source? | `evidence_id` |
| What portion compared? | `locator`, `compared_span` |
| What configuration? | `sample_rate`, `seed`, `config_ref` |
| What result? | `disposition`, `judgement` |
| What caused it? | `reason` |
| Layer 1 on the same material? | `layer1_pass` |
| When? | `audited_at` |

The register is append-only and **outside** the object model (no
lineage, no Intelligence Object). CI-1: configuration never enters
the judgement function.

### 3.6 What is deliberately NOT implemented

- **T03.2.3** published hallucination/drift rates (consumes these records).
- **T03.1.6** contradiction detection.
- Auto-raising the sample rate on elevated drift (S-5 operational
  policy; no empirical distribution yet; 5% remains the initial value).
- Closing M-67.
- Flipping `AnchorVerifier.covers_paraphrase_drift`.
- Recreating T03.2.1's `install_anchor_verification`.
- Re-extraction / second model pass (forbidden by S-5 vs N-4).
