## 3. The design (what is built, and why this shape)

### 3.1 What already exists (and is therefore NOT rebuilt)

- `oip/claim.py` (T01.7.2a): the four-component `Claim`, `Quantity`
  (mandatory precision), `assess_equivalence` (the four-condition test,
  four verdicts, reason on every result), `MERGE_POLICY`, and 45 pinned
  tests. Untouched by this task (byte-pinned in the verifier).
- `ExtractionRequest` (T03.1.1): enforces every component at
  construction and never defaults; `as_claim()` projects.
- `FactRegistry.assess_all / find_equivalent` (fact.py, untouched):
  the equivalence consumers.
- T03.1.1's component gate: subject/predicate/value_text must appear at
  the anchored span (S-5 layer 1); the qualifier travels verbatim as
  `qualifying_context`.

### 3.2 The gap this task fills

`as_claim()` is an *unguarded projection*: it cannot fail, because the
request already validated. That makes AC1 true by construction but
undemonstrated, and leaves AC2 with a real hole: **a claim the structure
carries but comparison cannot** — a `Quantity` whose value or precision
is not a real number (`bool`), or is NaN/infinite, constructs fine,
passes every T03.1.1 gate, and produces a Fact whose claim can never be
judged equivalent to anything — itself included — because
`Quantity.agrees_with` arithmetic is undefined for such values. S-3's
"forced or rejected" duty is exactly this: decomposition must refuse
what the structure cannot carry, with the refusal recorded (N-10),
never papered over.

### 3.3 The decomposition capability (fail-closed, in `extraction.py`)

`decompose(request) -> Claim` — the explicit decomposition step of the
extraction engine:

1. **Projection**: the four S-3 components from the request (subject,
   predicate, qualifier, value) — byte-identical to the request; the
   qualifier's explicit-`NONE` discipline and the Quantity's
   precision-mandatory discipline are inherited from the ratified types.
2. **Fail-closed structural validation** (`DecompositionError`):
   - a supplied `Quantity` value/precision must be a real number
     (`int`/`float`, `bool` refused — `bool` is an `int` subtype in
     Python) and **finite** (`NaN`/`±inf` refused): such a value makes
     the comparison undefined;
   - the **self-equivalence witness** (AC2): `assess_equivalence(claim,
     claim)` must return `EQUIVALENT`. A claim that is not equivalent
     to itself does not support equivalence comparison — the minimal,
   mechanically checkable form of AC2, enforced at decomposition time.
3. **No invention**: decomposition adds, resolves or normalises
   nothing. Synonyms are not resolved (S-3: subject/predicate identity
   "still require judgement" — reported `NOT_EQUIVALENT`, never
   merged); qualifier containment is recognised only in the unambiguous
   case; compound inputs are carried verbatim as ONE claim (granularity
   is the extractor's duty — one request = one claim; M-19 stays open).

### 3.4 Extraction integration (fail-closed, N-10)

`extract()` replaces its unguarded `request.as_claim()` call with
`decompose(request)`, placed after the anchor gates (the decomposition
judges the verified claim). A `DecompositionError` refuses with a
recorded **`DECOMPOSITION_FAILED`** failure — new closed-set stage,
reason `NOT_DECOMPOSABLE`, `attempted=True` (the judgement ran). No
Fact is created; the positional anchor of a refused extraction is
never registered (T03.1.3 invariant). A non-decomposable claim thus
never reaches the store — S-3's "rejected" branch, with a complete
N-10 record.

### 3.5 Import budget

`extraction.py` already imports `Claim, EquivalenceResult, Quantity,
UNQUALIFIED` from `oip.claim`; the witness adds `assess_equivalence`
and `Verdict` to the **same** import. The module set stays exactly
`{acceptance, claim, contract, evidence, fact, store}` — 6 of 6, no new
module, module count stays 37, DAG unchanged. `claim.py`, `fact.py`,
`semantic.py`, `store.py`: untouched (byte-pinned in the verifier
against the `17de9af` state).

## 4. What is deliberately NOT implemented

- **T03.1.4** merge execution: `MERGE_POLICY` is reported (verdicts and
  actions), never executed. Equivalence remains a report; DUPLICATES
  links are T03.1.4's to write.
- **T03.1.5** claim-type classification: `claim_type` stays
  caller-stated.
- **M-19**: extraction granularity — no compound-claim splitting, no
  subject/predicate semantic resolution, no fuzzy matching. All stay
  OPEN.
- **M-20 / M-67**: fidelity and hallucination detection — structure
  work detects none of that; layers 2/3 and the sampled audit remain
  the open mechanisms.
- No change to `claim.py`, `fact.py`, `semantic.py`, `store.py`; no
  change to any T03.1.1/T03.1.3 test or behavior; the density report
  and all downstream behavior unchanged.
