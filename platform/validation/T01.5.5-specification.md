## 5. Architectural constraints

1. **C1 — Only `assertion_confidence` is governed** (S-1 Known Tensions).
2. **C2 — Never change a confidence score.** Conformance observes; it does not adjust.
3. **C3 — No statistical calibration.** O2 is P8 (`T08.3.5`).
4. **C4 — No invented thresholds.** The five ranges are quoted from S-1 and must match `ConfidenceBand.for_value()` exactly.
5. **C5 — No new confidence vocabulary.** Five bands only; no sixth label, no sub-bands.
6. **C6 — Alternative-counting is judgement, supplied by the engine.** S-1 makes it *observable*, not *computable*. The platform cannot count alternatives for an engine; it can only record the count the engine declares and check it against the band. **Inventing a counting algorithm would fabricate the rubric.**
7. **C7 — Preserve acceptance, lifecycle, lineage, persistence, ownership** unchanged.
8. **C8 — Comparability is argued, not demonstrated** — must be reported honestly.
9. **C9 — Rubric version recorded**, so `T08.3.5` can retain prior calibration for comparison.
10. **C10 — Fail closed** where unspecified.

## 6. What each acceptance criterion requires

**AC1 — "Rubric bands referenced at assertion."** S-1 defines each band by range + criterion + test. A conformance check must resolve an asserted value to its band and expose the criterion the engine was supposed to apply. This is a *reference*, not a recomputation.

**AC2 — "Deviations recorded."** A deviation is a mismatch between the band the engine's declared alternative-count implies and the band its numeric value falls in. S-1's table makes this checkable **only when the engine declares its alternative count**, because the count is the observable criterion. Where no count is declared, conformance is **UNASSESSED** — not "conformant". Recording, never correcting (C2, R-1).

**AC3 — "Cross-engine comparison documented as rubric-dependent."** S-1: comparability *"is argued, not demonstrated"* until O2. Any cross-engine comparison must carry that qualification.

## 7. Unresolved ambiguities — surfaced, NOT resolved

| # | Ambiguity | Fail-closed treatment |
|---|---|---|
| **A1** | S-1 gives a *test* per band ("Are there ≥2 equally good alternatives?") but no field in which an engine records its answer. No ratified attribute exists for the alternative count. | **Do not add an attribute to the object model** (C7 — no object-model change). The conformance layer accepts a declared count as an *optional input to the check*, and reports `UNASSESSED` when absent. The absence of a ratified field is surfaced as a specification gap, not filled. |
| **A2** | S-1's bands map counts to ranges only loosely: NEGLIGIBLE says "would likely reach a different conclusion", WEAK "≥2 equally good alternatives", MODERATE "exactly one credible alternative", STRONG "alternatives require extra assumptions", VERY_STRONG "no non-contradictory alternative". Only WEAK, MODERATE and VERY_STRONG give a countable test. | Implement **only** the three countable mappings S-1 states literally (0 → VERY_STRONG, 1 → MODERATE, ≥2 → WEAK). NEGLIGIBLE and STRONG are **qualitative** in S-1 (reviewer disagreement; assumption-dependence) and are **not** derivable from a count. A count-based check against those bands returns `UNASSESSED`, never a deviation. Inventing a count for them would fabricate thresholds. |
| **A3** | Is a deviation an error that should block acceptance? | **No.** No ratified source makes calibration an acceptance rule; V1–V12 do not include it, and C7 forbids modifying acceptance. Deviations are **recorded**, exactly as AC2 says. |
| **A4** | What is the rubric "version"? | S-1 is version-identified only by its decision ID and ratification date. Use those verbatim; invent no version scheme. |
| **A5** | Does the rubric govern `effective_confidence` or `evidential_support`? | **No** — S-1 Known Tensions restricts it to `assertion_confidence`. Both others are explicitly out of scope. |
| **A6** | Per-stage IOM §2.3 bases — are they thresholds? | IOM says **"indicative only, not thresholds"**. Not enforced. |

## 9. Implementation plan

Smallest architecture-compliant change. New module only; **no edit to any existing production file**.

**Step 0 — verify** the implemented band boundaries equal S-1's table exactly. If they diverge, that is a defect to surface, not to paper over.

**Step 1 — `oip/calibration.py`.** `BandCriterion` (frozen): band, range, observable criterion, test question, two anchors — all quoted from S-1. `CALIBRATION_RUBRIC`: the five criteria. `RUBRIC_ID = "S-1"`, `RUBRIC_RATIFIED = "2026-08-02"`.

**Step 2 — conformance check.** `ConformanceOutcome`: `CONFORMANT` / `DEVIATION` / `UNASSESSED`. `assess_assertion(value, alternative_count=None)` → frozen `CalibrationAssessment` carrying band, criterion, outcome, and the rubric identity. Count-based checking only for the three countable bands (A2).

**Step 3 — deviation record.** `CalibrationDeviation` (frozen) + `CalibrationRegister` (append-only, thread-safe), outside the object model, recording deviations without altering any value.

**Step 4 — cross-engine comparison.** `compare_across_engines()` returning a result that **carries the rubric-dependency qualification** and `comparability_demonstrated = False` until O2.

**Explicitly NOT built:** any statistical/empirical calibration (P8, `T08.3.5`); any alternative-counting algorithm (C6); any new object attribute (C7); any acceptance-rule change (A3); any change to `evidential_support` or the ceiling (A5, OQ-34); any new band or threshold (C4, C5).
