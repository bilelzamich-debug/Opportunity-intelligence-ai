## 3. What is built (the three acceptance criteria)

### AC1 — Sufficiency threshold enforced

The engine **derives** `independent_source_count` — the number of distinct
independence keys across the Evidence beneath the supporting Facts — and
refuses any request below the S-4 floor **before constructing a Problem**
(stage `INSUFFICIENT_SOURCES`). The count is computed from **identity**,
per S-4's own words ("independent means after independence grouping:
syndicated or commonly-owned sources count once") and N-16's Tier-1
propagation rule ("derived from its inputs' counts and their independence
relationships"):

* for each supporting Fact, for each of its attachments, the referenced
  Evidence's `provenance.independence_key` (`source_independence_group`
  when carried, else `source_identifier` — the ratified T02.1.3 key);
* distinct keys only: two Facts from sources sharing an independence
  group count **once**; the same Evidence beneath two Facts counts
  **once**; per-Fact counts are never summed blindly;
* only Evidence that resolves **and is ACTIVE** contributes a key
  (mirroring the `EvidenceRegistry.independent_sources()` precedent);
  a supporting Fact whose Evidence is entirely unresolved is itself a
  refusal (`EVIDENCE_UNRESOLVED`), never a silent zero.

Exactly 2 independent sources qualifies. 1 does not. 0 does not. The
store's own P-V1 re-checks the declared count at acceptance — the engine's
gate is a precondition, never a bypass.

### AC2 — Single-fact restatement rejected (P-V6)

P-V6 is **authoritative at acceptance** (`store.write_problem` →
`pv6_not_a_single_fact_restatement`, with the store-wired
`fact_claim_text` hook). The engine does not duplicate the rule; it routes
every hypothesis through acceptance, so both prongs fire exactly as
ratified:

1. a Problem resting on a single Fact is rejected
   (`rests_on_a_single_fact`);
2. a `problem_statement` identical (verbatim form) to a supporting Fact's
   claim is rejected however many Facts are attached.

An engine-path request that survives the engine gates and fails P-V6 is
recorded as `STORE_REJECTED` — attempted, judged, refused by the
authoritative rule.

### AC3 — inference_basis references specific Facts

The request carries the basis: one `FactContribution` per supporting Fact
(what that Fact establishes) plus the `synthesis` (why they **together**
indicate a deficiency). The engine requires **exact coverage**: every
supporting Fact is represented, no Fact outside the supporting set is
represented, duplicates are refused (the `InferenceBasis` type enforces
the last two; the engine enforces the first). P-V5 re-checks at
acceptance.

## 4. Engine API (public surface of `oip/inference.py`)

| Symbol | Purpose |
|---|---|
| `InferenceError` | Base class for inference violations |
| `InferenceRefusedError(InferenceError)` | A refusal; carries the `InferenceFailure` |
| `InferenceStage(str, Enum)` | Closed set of refusal stages (below) |
| `InferenceFailure` (frozen) | One recorded refusal: `fact_refs`, `stage`, `reason`, `detail`, `failed_at`, `engine_configuration_ref`; `engine` → `Engine.PROBLEM_INTELLIGENCE` [V7/K8]; `attempted` derived from stage [N-10]; `as_failure_record()` projects into the platform `FailureRecord` shape |
| `InferenceLog` | Append-only refusal register [N-10]; `attach(failure_store)` projects every failure by the ratified `record` surface, exactly as `ExtractionLog` does |
| `InferenceRequest` (frozen) | One hypothesis, fully specified by the inferer (see §5) |
| `InferenceOutcome` (frozen) | One accepted inference, traceable end to end: the persisted `Problem`, supporting fact refs, evidence refs, `independence_keys`, `independent_source_count`, `source_type_count`, `evidential_support`, `assertion_confidence` |
| `infer(request, *, store, log, clock=utc_now)` | The engine. Returns `InferenceOutcome` or raises `InferenceRefusedError` with the failure recorded in the log first |

### Refusal stages (closed set, [N-10])

| Stage | Meaning | `attempted` |
|---|---|---|
| `INVALID_REQUEST` | Malformed request / not a request / basis-set mismatch / bad confidence | No — never judged |
| `FACT_NOT_FOUND` | A referenced object does not exist, or exists but is not a Fact [N-14] | No |
| `FACT_NOT_ACTIVE` | A supporting Fact is not `ACTIVE` (P-I2 as an input precondition) | No |
| `EVIDENCE_UNRESOLVED` | A supporting Fact's attachment Evidence does not resolve in the store | No |
| `TEMPORAL_CONFLICT` | An upstream `observed_at` is after `now`; V8 could not hold | No |
| `INSUFFICIENT_SOURCES` | Derived independent-source count below the S-4 floor of 2 | **Yes** — judged |
| `STORE_REJECTED` | The authoritative acceptance path refused (P-V1..P-V6 / V1..V12) | **Yes** — judged |

Not-attempted vs attempted is derived from the stage and can never drift
from the record — the extraction convention. There is deliberately no
EMPTY stage: one request is one hypothesis; "found nothing" has no
meaning for a supplied hypothesis, and inventing it would collapse N-10's
distinctions rather than preserve them.

## 5. Request model [N-4]

`InferenceRequest` carries **every** value the Problem requires. The
engine invents nothing — not the statement, not the population, not
severity, not frequency, not the domain, not the supporting Facts, not
the basis, not the confidence:

| Field | Type / constraint |
|---|---|
| `fact_refs` | `tuple[str, ...]`, non-empty, no duplicates — the supporting Facts (plural expected; a single Fact is judged at acceptance by P-V6) |
| `problem_statement` | non-empty — the deficiency, stated solution-independently (P-V2 judges it; the engine does not rewrite it) |
| `affected_population` | non-empty (P-V3 judges specificity) |
| `severity`, `frequency` | non-empty free text — **no scales**: M-12 is open, bands land at T04.1.4 |
| `problem_domain` | non-empty free text — **no taxonomy**: M-21 is open, lands at T04.1.6 |
| `contributions` | `tuple[FactContribution, ...]` — exactly the supporting set, one per Fact [P-V5] |
| `synthesis` | non-empty — why the Facts **together** indicate a deficiency [P-V5/P-V6] |
| `inference_confidence` | `float` in [0.0, 1.0] — the inferer's own certainty, R-3's interpretive component |
| `population_size_estimate` | optional `int ≥ 0` |
| `existing_workarounds`, `problem_persistence`, `cost_indication` | optional non-empty strings |
| `engine_configuration_ref` | non-empty, default `"problem-inference-v1"` [N-4/N-7] |

Optional fields are never defaulted to content; absence stays absence.

## 6. Inference flow (ordered, fail-closed)

1. **Request validity** — non-request argument, empty/duplicate fact refs,
   basis-set mismatch (coverage ≠ exactly the supporting set),
   out-of-range confidence → `INVALID_REQUEST`.
2. **Fact resolution** — every `fact_ref` must resolve in the store **and**
   be a `FACT` [N-14 direct-input type] → else `FACT_NOT_FOUND`.
3. **Lifecycle eligibility** — every supporting Fact must be `ACTIVE`
   [P-I2 as an input precondition] → else `FACT_NOT_ACTIVE`.
4. **Evidence resolution** [N-14 grant] — every attachment's Evidence must
   resolve → else `EVIDENCE_UNRESOLVED`. Non-ACTIVE Evidence contributes
   no independence key (fail-closed toward rejection, never toward
   invention).
5. **N-16 derivation** — distinct `independence_key`s across ACTIVE
   Evidence beneath the supporting Facts → `independent_source_count`.
   Below the S-4 floor (2) → `INSUFFICIENT_SOURCES`. Never sums per-Fact
   counts; never double-counts a group; never invents identity.
6. **Temporal consistency** — `observed_at` = max of supporting Facts'
   `observed_at`; if after `now` → `TEMPORAL_CONFLICT` (V8 pre-checked;
   acceptance re-checks).
7. **Confidence [R-3, S-2, IOM §3.3]** — `evidential_support` =
   `compute_support(SupportInputs(independent_source_count,
   source_type_count, corroboration_depth=len(fact_refs),
   upstream_support=(each Fact's effective_confidence,)))` — P6 bounds it
   by the contributing Facts; `assertion_confidence` =
   `inference_confidence` (supplied, never invented); upstream ceiling =
   min of supporting Facts' effective confidence (V5 holds by
   construction and is re-checked at acceptance).
8. **Composition** — identity from `store.allocator` [extraction
   precedent]; `produced_by_engine=PROBLEM_INTELLIGENCE` [V7];
   `derives_from` = the supporting Facts (`SUPPORTS` = the same subset,
   type-enforced [R-6]); four-part explanation [N-13] naming the Facts,
   the criteria (S-4, N-16, P-V5, P-V6, R-3) and the reasoning,
   including the derived count and keys; `status=ACTIVE`,
   `status_reason=None` — acceptance **is** the IOM's PROPOSED→ACTIVE
   transition, the established platform interpretation (Fact path);
   `independent_source_count` = the derived count [N-16 Tier 1].
9. **Persistence** — `store.write_problem(problem)` and nothing else. A
   `WriteRejectedError` → `STORE_REJECTED` (detail carries the
   acceptance failure). The store's atomicity guarantees no partial
   state: object map, lineage index, graph and registry move together or
   not at all. The engine never writes to `ProblemRegistry`, the graph,
   or store internals.

## 7. What is deliberately NOT implemented

* **T04.1.2** solution-independence across versions (P-I1 deepening) —
  P-V2's lexical check at acceptance is all that runs here.
* **T04.1.3** affected-population identification — P-V3 judges what the
  request supplies; the engine widens nothing.
* **T04.1.4** severity/frequency ordinal bands (M-12 OPEN) — presence
  only (P-V4); free text, never ranked.
* **T04.1.5** problem identity/deduplication (M-22 OPEN) — the engine
  never merges, never links DUPLICATES, never compares against existing
  Problems; under-merge is the only possible outcome.
* **T04.1.6** problem taxonomy (M-21 OPEN) — `problem_domain` is
  unconstrained free text.
* **T04.2.1** P4 exit — a later gate.
* No LLM integration, no network, no external API, no generalized
  observability, no sampling-rate correction (R10), no new lifecycle
  path, no new decision semantics: every rule applied here is already
  ratified.
